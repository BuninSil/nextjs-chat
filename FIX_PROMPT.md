# Задание на исправление — Fast VPN (mlbb-overlay)

Ты дорабатываешь Android-приложение `mlbb-overlay/` (Kotlin + нативный C `zdtun`, ядра sing-box/Xray).
Ниже список подтверждённых багов безопасности и стабильности с точными местами и тем, что надо сделать.
Правь по приоритету (P0 → P3). Ничего, кроме перечисленного, не ломай: UX, игровой режим, автоподбор сервера должны остаться как есть.
После каждого блока — как проверить, что фикс рабочий.

---

## P0 — критично

### 1. Автообновление без проверки целостности APK
**Файлы:** `Updater.kt` (`check`, `download`, `install`), `AutoUpdate.kt` (`runInBackground`, `notifyReady`).
**Проблема:** апдейтер выбирает релиз по тегу `mlbb-v<versionCode>` и качает APK, сверяя **только размер файла**. Подписи/хэша артефакта от разработчика нет. Фоновый джоб каждые 6 часов молча качает APK и шлёт уведомление «нажми, чтобы установить». Кто сможет опубликовать релиз с бóльшим номером или подменить ассет — раздаёт обновление всем.
**Сделать:**
- Публиковать рядом с APK в релизе файл с SHA-256 (и, лучше, открепляемой подписью, напр. minisign/cosign). Публичный ключ разработчика зашить в `BuildConfig`.
- В `download()` после скачивания считать SHA-256 файла и сравнивать с ожидаемым из релиза; при несовпадении — удалять файл и бросать ошибку. Если есть подпись — проверять её публичным ключом до установки.
- Фоновую авто-загрузку не превращать в тихий авто-инсталл: уведомление оставить, но установку запускать только по явному тапу (сейчас так и есть — не регрессировать).
**Проверка:** подменить ассет в тестовом релизе (другой APK того же размера) → апдейтер отклоняет с ошибкой хэша; валидный апдейт ставится.

### 2. Локальные SOCKS/HTTP-прокси без авторизации на 127.0.0.1
**Файлы:** `BoxConfig.kt:170-171` (`mixed-in`), `XrayCore.kt:134-146` (SOCKS-входы XHTTP и bypass, `auth: "noauth"`).
**Проблема:** любое приложение на телефоне коннектится к `127.0.0.1:<порт>` и гоняет свой трафик через платный туннель пользователя; порт перебирается за секунды. (Clash API при этом нормально закрыт случайным секретом — его не трогать.)
**Сделать (любой из вариантов, по возможности оба):**
- Включить username/password-auth на `mixed-in` и на SOCKS-входах Xray: генерировать креды вместе с портами (как уже делается `secret` для Clash API, `SecureRandom`), передавать их в `Net.open()` (SOCKS-прокси с авторизацией) и в `ServerTester` для `mixed`-замеров.
- Либо для `mixed-in` не слушать общий loopback, а использовать uid-фильтр/отдельный механизм так, чтобы вход был доступен только своему процессу.
**Проверка:** с запущенным VPN из `adb shell` `curl --socks5 127.0.0.1:<port> https://api.ipify.org` без кредов → отказ; свои замеры/`Net` продолжают работать.

### 3. Нет kill switch, утечка реального IP при переподключении
**Файлы:** `BoxConfig.kt:154` (`strict_route=false`), `BoxConfig.kt:145-168`, `BoxVpnService.kt:581-599` (авто-переключение в compat: `stop → sleep(1500) → connect`), `onRevoke`.
**Проблема:** при `strict_route=false`, падении ядра, `onRevoke`, смене сети и во время авто-реконнекта (1.5+ сек без туннеля) трафик идёт с реального IP. Приложение само ничего не блокирует.
**Сделать:**
- Выставить `strict_route = true` в tun-конфиге.
- Переподключение в режим совместимости делать без полного сноса tun: пересобрать конфиг/рестартовать ядро, не отдавая интерфейс (минимизировать окно без туннеля). Если полностью убрать окно нельзя — на это время не выпускать трафик.
- В UI явно вести пользователя к системному «Always-on VPN» + «Блокировать соединения без VPN» (ссылка/подсказка на видном месте), т.к. программно это приложение включить не может.
**Проверка:** включить VPN, во время трафика переключить Wi-Fi↔LTE и отдельно дождаться авто-switch в compat; на стороне сервера/через сторонний монитор убедиться, что реальный IP не светится.

## P1 — высокий (стабильность)

### 4. Поворот экрана роняет UI и течёт памятью
**Файлы:** `MainActivity.kt` — долгие операции `:695` (гео-база), `:839` (подключение к внешнему клиенту), `:946` (обновление подписки), `:990` (обновление через VPN), `:1082` (тест скорости); манифест `MainActivity`.
**Проблема:** нет `screenOrientation`/`configChanges` → поворот пересоздаёт Activity. Операции держат `val progress = AlertDialog...show()` и обновляют `lateinit`-вьюхи/зовут `progress.dismiss()` на уничтоженной Activity из рабочего потока → `WindowLeaked`, застрявший диалог, утечка Activity на 20+ сек.
**Сделать:**
- Вынести долгие операции из Activity: держать их в `ViewModel` (`viewModelScope`/корутины) или в сервисе, а UI подписывать на состояние. Диалоги прогресса пересоздавать по состоянию, а не хранить ссылку на старое окно.
- Минимум-вариант, если без рефакторинга: все диалоги прогресса закрывать в `onDestroy`; перед обновлением UI проверять `!isDestroyed && !isFinishing`; worker не должен держать ссылку на Activity (использовать `applicationContext` и колбэки через слабую ссылку/флаг).
**Проверка:** на медленной сети начать обновление подписки/тест скорости и крутить экран — в `logcat` нет `WindowLeaked`/`View not attached`; в Android Studio Profiler нет роста числа инстансов `MainActivity`.

### 5. Оверлей мигает/ломается после Doze и убийства процесса
**Файл:** `MonitorService.kt:96-107` (`onStartCommand` возвращает `START_STICKY`, читает порт/секрет только из intent), `:137-150`.
**Проблема:** после убийства процесса система рестартует сервис с `intent == null` → `fixedApiPort = 0` → уходит в ветку «внешний клиент» с не теми настройками, 5 раз фейлит и сам себя гасит. Параллельно `BoxVpnService` поднимает свой `MonitorService` с новыми портами → гонка, оверлей дёргается.
**Сделать:** вернуть `START_NOT_STICKY` для `MonitorService` (его владелец — `BoxVpnService`, он перезапустит с верными портами). Дополнительно: не запускать мониторинг при `port == 0` в режиме встроенного VPN (ранний выход с логом).
**Проверка:** включить VPN, через `adb shell am kill dev.mlbb.overlay` (или форсить Doze) — после восстановления оверлей поднимается один раз с правильными портами, без ошибки «VPN-клиент перестал отдавать список».

## P2 — средний

### 6. Секрет Clash API утекает в «Отчёт о проблеме»
**Файлы:** `SettingsActivity.kt:410-429` (хелпер `input()` логирует значение любого поля), `:262` (поле `secret`); потребители — `AppLog`, `Report`.
**Проблема:** `AppLog.set("поле «$hint»", s?.toString())` пишет значение секрета в `applog.txt`, который целиком попадает в отчёт, отправляемый разработчику. При этом заявлено «паролей не пишем».
**Сделать:** не логировать значения чувствительных полей. Либо логировать только факт изменения (без значения), либо завести флаг `sensitive` у `input()` и для `secret`/паролей не писать значение; для таких полей также задать `inputType = TYPE_TEXT_VARIATION_PASSWORD`. Пройтись по существующему `applog`-пайплайну, чтобы старые секреты не всплывали.
**Проверка:** изменить поле `secret`, собрать отчёт — значения секрета в тексте нет.

### 7. `ruDirect = true` по умолчанию: реальный IP мимо VPN
**Файлы:** `AppSettings.kt:123` (дефолт `true`), `BoxConfig.kt:209-218`.
**Проблема:** по умолчанию весь трафик и DNS к RU-доменам (банки, госуслуги, VK, Яндекс, маркетплейсы, kaspersky…) идут напрямую — реальный IP виден этим сервисам и провайдеру. Включено молча и шире, чем нужно.
**Сделать:** решить продуктово — либо дефолт `false`, либо явный onboarding-тумблер с понятным пояснением «эти сайты пойдут мимо VPN с вашим реальным IP». Список доменов сузить до того, что действительно требует российского IP (банки/госуслуги), не загонять туда видео/маркетплейсы по умолчанию.
**Проверка:** на свежей установке убедиться, что поведение соответствует выбранному решению и пользователь о нём проинформирован.

### 8. Нет `FLAG_SECURE` — токен подписки утекает в скриншоты/недавние
**Файлы:** экраны с подпиской/серверами (`MainActivity` диалог подписки ~`:893`, `ServersActivity`), оверлей.
**Проблема:** `FLAG_SECURE` нигде не стоит. Поле подписки префилит полную ссылку с токеном; она попадает в скриншоты, запись экрана и кэш превью «Недавних приложений».
**Сделать:** на экранах/диалогах, где видны ссылка подписки и адреса серверов, выставлять `window.addFlags(WindowManager.LayoutParams.FLAG_SECURE)`. В поле подписки маскировать токен (показывать `https://host/...****`, полностью — по тапу «показать»).
**Проверка:** открыть экран подписки, свернуть в «Недавние» — превью пустое/замазано; скриншот системой блокируется.

### 9. Парсер `.mmdb` падает на недоверенном файле
**Файлы:** `MmdbReader.kt:124-170` (разыменование указателей без защиты от циклов/границ, `size` без потолка), `SettingsActivity.kt:514-520` (`importDatabase` ловит только `Exception`).
**Проблема:** импорт вредоносного `.mmdb` с циклическим указателем → `StackOverflowError` (это `Error`, `catch(Exception)` его не ловит) → краш; раздутый `size` → OOM.
**Сделать:**
- В `Decoder` ограничить глубину рекурсии / вести набор посещённых офсетов и падать на цикле понятной ошибкой; проверять, что `base + ptr` и `pos + size` в пределах буфера.
- Ввести разумный потолок на `size` для string/map/array.
- В `importDatabase` ловить `Throwable` (или явно `StackOverflowError`/`OutOfMemoryError`) вокруг `MmdbReader(tmp)` и показывать «файл повреждён», не роняя приложение.
**Проверка:** скормить mmdb с pointer-циклом через «Импортировать базу» → приложение показывает ошибку, не крашится. (Могу дать PoC-файл.)

## P3 — низкий / визуал / комплаенс

### 10. Непрерывная перерисовка анимаций жрёт батарею
**Файлы:** `StarField.kt:88-91`, `GlobeView.kt:216`, `ConnectRing.kt:176`.
**Сделать:** останавливать анимацию «полёта» звёзд через несколько секунд после подключения (как уже сделано для покачивания глобуса), или резать до 1–2 fps в спокойном состоянии. Прекращать перерисовку, когда экран не на переднем плане.
**Проверка:** на подключённом VPN главный экран в покое — нет постоянного ~30 fps (видно по GPU rendering / Energy Profiler).

### 11. Джанк при прокрутке
**Файл:** `MainActivity.kt:448` — `setOnScrollChangeListener { ring.invalidate(); stars?.invalidate() }`.
**Сделать:** не форсить полную перерисовку звёзд на каждый пиксель скролла — обновлять позицию якоря реже (throttle) или двигать анимацию через трансляцию, а не `invalidate()` всего поля.

### 12. Оверлей перехватывает тапы поверх игры
**Файл:** `OverlayController.kt:22-33`.
**Сделать:** по умолчанию добавить `FLAG_NOT_TOUCHABLE` (плашка не ест касания), а перетаскивание включать отдельным режимом (напр. долгий тап/ручка), либо делать окно касаемым только во время перемещения. Убрать `FLAG_LAYOUT_NO_LIMITS` или учитывать вырез/статусбар, чтобы плашка не уезжала под них.

### 13. Бэкап экспортирует секреты открытым текстом
**Файл:** `Backup.kt:243-295`.
**Сделать:** при шаринге бэкапа предупреждать, что внутри ссылка подписки и ключи серверов; по возможности — опциональное шифрование паролем. Токен в файле не обязателен для переноса настроек — рассмотреть исключение `subUrl` из бэкапа или его маскирование.

### 14. DoS при разборе гигантской «подписки»
**Файл:** `Subscription.kt:308-317` (`b64`), `:341-359` (`parseAll`).
**Сделать:** ограничить максимальный размер входа подписки (напр. несколько МБ) до декодирования base64/разбора строк, с понятной ошибкой.

### 15. Лицензии (комплаенс при распространении APK)
**Файлы:** корень репозитория, `README.md:572-576`, экран «О программе».
**Сделать:**
- Добавить в корень полноценный `LICENSE` (sing-box встроен → GPL-3.0 распространяется на приложение) и «письменное предложение исходников» в дистрибутиве/релизе.
- Для zdtun (LGPL-3.0) обеспечить возможность замены/пересборки библиотеки (объектники или инструкция).
- Атрибуцию DB-IP (CC BY 4.0) показать в самом UI приложения (экран «О программе»/«Лицензии»), не только в README/assets.

## Что НЕ трогать (проверено, работает корректно)
- Генерация `secret` Clash API (`SecureRandom`) — ок.
- Загон IPv6 в tun с `reject` — утечки IPv6 нет.
- `allowBackup=false`.
- Нативный `zdtun_parse_pkt` (пофаззен, крашей нет), проверки `FD_SETSIZE`.
- Переподключение `BoxVpnService`/`CaptureVpnService` после Doze/kill (проблема только в `MonitorService`, см. п.5).
- Снятие хендлер-тикеров и `overlay.hide()` в `stop*/onDestroy`.

## Порядок работы
1. Делать по одному пункту = один коммит с осмысленным сообщением.
2. Собрать проект (`./gradlew assembleDebug`), прогнать на устройстве/эмуляторе ключевые сценарии (подключение, подбор сервера, игровой режим, обновление подписки).
3. По пунктам 1–5 приложить к PR, как именно проверял (команды/шаги из блоков «Проверка»).
