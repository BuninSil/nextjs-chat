# Fast VPN (mlbb-overlay) — отчёт по безопасности

**Дата:** 2026-10-12
**Объект:** `mlbb-overlay/` — Android-клиент VPN (Kotlin + нативный C `zdtun`), ядра sing-box (libbox) и Xray, оверлей для Mobile Legends, импорт подписок, автообновление APK, офлайн-гео DB-IP.
**Подход:** чёрно-белый ящик по исходникам. Нативная часть (`zdtun_parse_pkt`) пофаззена на хосте под ASAN/UBSan. Что требует реального устройства — помечено как «нужен телефон» с шагами.

> Код не менялся — только отчёт, как и просили.

## Детали

### F1 — Приватный ключ подписи в репозитории (Critical)
`app/build.gradle.kts`:
```kotlin
getByName("debug") {
    storeFile = file("debug.keystore")
    storePassword = "android"
    keyAlias = "androiddebugkey"
    keyPassword = "android"
}
```
`debug.keystore` закоммичен (`keytool -list` подтверждает: `CN=Android Debug`, валиден до 2054). Релизный APK подписывается именно им (в CI собирается `assembleDebug`).

**Чем грозит.** Подпись Android защищает обновления по принципу «новый APK подписан тем же ключом». Ключ и пароль публичны → эта защита обнуляется: кто угодно собирает APK с `applicationId = dev.mlbb.overlay`, `versionCode` выше текущего, подписывает этим ключом, и система ставит его **обновлением поверх** настоящего приложения (с его разрешениями: VPN, оверлей, установка пакетов). В связке с F2/F3 это полноценный захват.

**Воспроизведение.**
```bash
keytool -list -v -keystore mlbb-overlay/app/debug.keystore -storepass android   # ключ открывается
```
Дальше — собрать любой APK с тем же package и бóльшим versionCode, подписать этим keystore, выложить как «обновление».

**Как чинить.** Убрать keystore из репы и истории (`git filter-repo`), считать ключ скомпрометированным и сгенерировать новый релизный, хранить в GitHub Secrets, подписывать `assembleRelease`. До ротации любой APK, собранный до сих пор, не доверять.

### F2 — Автообновление без проверки целостности (High)
`Updater.check()` берёт `releases` с `api.github.com` (TLS валиден — ок), выбирает релиз с тегом `mlbb-v*`, где `versionCode > BuildConfig.VERSION_CODE` и `sha != BuildConfig.GIT_SHA`. `download()` качает ассет и сверяет **только размер** (`apkSize`). `AutoUpdate.Job` каждые 6 часов **молча качает** APK в фон и шлёт уведомление «нажми, чтобы установить»; есть `REQUEST_INSTALL_PACKAGES`.

**Чем грозит.** Нет пиннинга ключа GitHub, нет подписи/хэша ассета от разработчика. Любой, кто сможет опубликовать релиз `mlbb-v<N>` с бóльшим номером или подменить ассет в существующем релизе (скомпрометированный аккаунт/токен CI), раздаёт обновление всем пользователям. А так как ключ подписи публичный (F1), даже «тот же разработчик» ничего не доказывает. MITM: при поднятом VPN `Net.open()` гоняет апдейт-запрос **через SOCKS выбранного сервера** (`Net.kt:16-19`) — то есть через инфраструктуру VPN-провайдера; TLS к GitHub это пока спасает, но вся модель держится на одном TLS и нулевой подписи артефакта.

**Как чинить.** Подписывать APK/манифест обновления отдельным ключом разработчика и проверять подпись/SHA-256 перед установкой; не ставить фоново без явного действия; рассмотреть пиннинг.

### F3 — Локальные прокси без авторизации (High)
`BoxConfig.build()`:
```kotlin
val mixed = JSONObject().put("type", "mixed").put("tag", "mixed-in")
    .put("listen", "127.0.0.1").put("listen_port", ports.mixed)   // ← auth нет
```
`XrayCore.start()` поднимает SOCKS-входы `auth: "noauth"` на `127.0.0.1` для каждого XHTTP-сервера и для «обхода блокировок». Правило `mixed-in → probe` отдаёт этот трафик через выбранный сервер.

**Чем грозит.** Любое другое приложение на телефоне (без спец-разрешений) подключается к `127.0.0.1:<порт>` и:
- гоняет свой трафик через **платный туннель** пользователя (кража канала/трафика подписки);
- через `probe`-выход может выяснять, что это за сервер/выход.
Порты случайные, но перебор `1024..65535` тривиален — это ровно то, что делает сам же `ClashApi.find()` (`ClashApi.kt:316-329`). Clash API, в отличие от прокси, прикрыт случайным секретом (`SecureRandom(16)` — это сделано правильно).

**Воспроизведение (нужен телефон).** На устройстве с запущенным VPN из другого приложения / через `adb`: просканировать loopback, найти mixed-порт, сделать `curl --socks5 127.0.0.1:<порт> https://api.ipify.org` — вернётся IP VPN-выхода.

**Как чинить.** Либо не слушать внешне доступный loopback для mixed-входа (он нужен только самому приложению — задать логин/пароль и передавать их в `Net`/`ServerTester`), либо биндить на UDS/использовать uid-фильтр.

### F4 — Нет kill switch, утечки при переподключении (High)
`strict_route=false` всегда (`BoxConfig.kt:154`). Приложение само не блокирует трафик при отсутствии туннеля. Авто-переключение в режим совместимости (`BoxVpnService.writeLog`, `:581-599`) делает `stop(ctx) → sleep(1500) → connect(ctx)` — полторы+ секунды без туннеля. При краше ядра/`onRevoke`/смене Wi-Fi↔LTE — то же окно. IPv6, кстати, закрыт нормально (загоняется в tun и `ip_version 6 → reject`, `BoxConfig.kt:148-178`) — утечки IPv6 нет, это в плюс.

**Чем грозит.** В эти окна весь трафик (включая заблокированные сервисы) уходит с реального IP провайдера. «Защита» — только системный тумблер «Блокировать соединения без VPN», который приложение включить не может и в UI о нём не напоминает на видном месте.

**Как чинить.** `strict_route=true`; переподключение без полного `stop` (пересборка конфига без сноса tun); явно вести пользователя к «Always-on VPN + Block without VPN».

### F5 — Парсер `.mmdb` падает на недоверенном файле (Medium)
`MmdbReader.Decoder.decode()` для указателя делает `Decoder(base, base + ptr).decode()` без проверки на цикл и диапазон. MaxMind-спека запрещает указатель-на-указатель, но вредоносный файл так умеет → бесконечная рекурсия → `StackOverflowError`. Типы map(7)/array(11)/string(2) берут `size` без верхней границы (`size = 65821 + readUInt(3)`), а строка читает `buf.get(pos+k)`.

`SettingsActivity.importDatabase()` ловит **`Exception`**, а `StackOverflowError` — это `Error`, он пролетает мимо и ловится уже глобальным обработчиком в `App` → приложение крашится (и пишет crash-репорт).

**Чем грозит.** DoS: прислать пользователю «новую базу стран» `.mmdb` с циклическим указателем — импорт роняет приложение. OOM-вариант — через раздутый `size`.

**Воспроизведение.** Собрать минимальный mmdb, где data-секция содержит pointer A→B и B→A, скормить через «Импортировать базу». Могу сделать PoC-файл, если надо.

**Как чинить.** Лимит глубины/посещённых офсетов при разыменовании указателей, проверка `base+ptr` в границах, потолок на `size`, ловить `Throwable` вокруг `MmdbReader(tmp)`.

### F6 — Секрет Clash API утекает в «Отчёт о проблеме» (Medium)
`SettingsActivity.input()`:
```kotlin
override fun afterTextChanged(s: Editable?) {
    AppLog.set("поле «$hint»", s?.toString())   // ← пишет значение ЛЮБОГО поля
    ...
}
```
Через этот хелпер заводится поле `secret` (`:262`, Clash API-секрет внешнего клиента). `AppLog` и `Report` прямо декларируют: «Ссылок подписки, адресов серверов и паролей сюда не пишем». Это неправда — `secret` оказывается в `applog.txt`, а `Report.build()` вставляет весь applog в отчёт, который пользователь шлёт разработчику в Telegram/почту.

**Как чинить.** Не логировать значения полей (только факт изменения) или занести `secret`/пароли в денилист логирования; маскировать чувствительные поля (`inputType` password).

### F7 — `ruDirect=true` по умолчанию: реальный IP мимо VPN (Medium)
`AppSettings.load`: `ruDirect = p.getBoolean("ruDirect", true)`. `BoxConfig` при этом роутит `RU_SUFFIXES` + `geosite-category-ru` в `direct`. Список включает банки (Сбер, Тинькофф, ВТБ…), госуслуги, VK, Яндекс, маркетплейсы, kaspersky и т.д.

**Чем грозит.** По умолчанию и без явного согласия трафик и DNS к этим доменам идут напрямую — эти сервисы и провайдер видят реальный IP пользователя, который включил VPN в том числе чтобы этого избежать. Для банков это «фича», но включено молча и шире, чем банки.

**Как чинить.** Оставить на усмотрение пользователя (явный тумблер с пояснением), сузить список, не включать по умолчанию для всего подряд.

---

### F8 — Нет `FLAG_SECURE` (Medium)
`FLAG_SECURE` не выставлен нигде. Экран «Подписка» префилит полную ссылку подписки с токеном (`MainActivity.kt:~893`), экраны серверов показывают IP, оверлей рисует реальный IP боевого сервера поверх игры.

**Чем грозит.** Токен подписки и IP серверов попадают в скриншоты, запись экрана и, что важнее, в кэш превью «Недавних приложений» (хранится на диске). Любое приложение со скринкастом/скриншотом (или человек рядом) получает токен подписки = доступ ко всем серверам пользователя.

**Как чинить.** `window.addFlags(FLAG_SECURE)` на экранах с подпиской/серверами (как минимум), маскировать токен в поле.

### F9 / F10 / F11 / F12 / F13 — коротко
- **F9 (лицензии).** README честно пишет про GPL-3.0 sing-box и обязательство открыть исходники — но в корне нет файла `LICENSE`/`COPYING` под GPL-3.0 для самого приложения и нет «письменного предложения исходников» в дистрибутиве APK. Для zdtun `COPYING` есть (LGPL-3.0) — ок, но LGPL дополнительно требует возможности пересборки/замены библиотеки. DB-IP (CC BY 4.0) требует видимой атрибуции — в assets лежат `LICENSE-*`, в README упомянуто, но в UI самого приложения, которое ставит пользователь, атрибуции DB-IP не видно. Для распространения APK это дыры в комплаенсе.
- **F10 (бэкап).** `Backup.build()` сериализует все `prefs` кроме денилиста (`subUrl`, `apiSecret`, SOCKS-пароль там **остаются**) + `subscription.txt` целиком (UUID/пароли VLESS/Trojan/SS). Отдаётся через `ACTION_SEND` без шифрования. Ожидаемо для «переноса», но утечка всех ключей при отправке не туда.
- **F11 (`queries`).** `intent MAIN/LAUNCHER` даёт перечисление всех установленных приложений — чувствительно, но объяснимо выбором «какие приложения через VPN».
- **F12 (подписка-DoS).** `b64()`/`parseAll()` без лимита размера — гигантский вход роняет по памяти. Low (нужно самому вставить огромный текст).
- **F13 (экспорт компонентов).** VPN-сервисы `exported=true` — это требование системы, прикрыты `BIND_VPN_SERVICE`; `ShizukuProvider` под `INTERACT_ACROSS_USERS_FULL`. Явных незащищённых receiver/activity с опасным эффектом, которые дёргает чужое приложение, не нашёл. Единственная реальная локальная поверхность — F3.

## Топ-5 чинить первым

1. **F1 — выкинуть `debug.keystore` из репы и истории, ротировать ключ, подписывать релиз секретным ключом из GitHub Secrets.** Без этого всё остальное про обновления бессмысленно.

3. **F3 — закрыть локальный mixed-прокси (auth или не слушать внешне доступный loopback).**

5. **F6 — перестать писать значения полей (секрет Clash API) в applog/отчёт.**

## Что проверено и оказалось ок

- **Нативный разбор пакетов `zdtun_parse_pkt`** — пофаззен на хосте (ASAN+UBSan, ~8 млн мутаций IPv4/IPv6/TCP/UDP/фрагменты) — крашей, переполнений и UB не поймал. Границы длин IP/TCP/UDP проверяются.
- **`zdtun`/`tunbridge` дескрипторы** — `sock >= FD_SETSIZE` проверяется в обоих местах перед `FD_SET`; `MAX_NUM_SOCKETS=512`, `MAX_UDP_FLOWS=256` с пурджем — переполнения `fd_set` не видно.
- **Секрет Clash API** генерится `SecureRandom(16)` — нормально (в отличие от прокси-входов без auth).
- **IPv6-утечка** — IPv6 загоняется в tun и режется (`ip_version 6 → reject`), мимо туннеля не уходит.
- **`allowBackup=false`** — adb-бэкап отключён.
- **TLS к GitHub / Cloudflare / DB-IP** — обычный HTTPS, `network_security_config` разрешает cleartext только для `127.0.0.1`/`localhost` (для Clash API) — остальное валидируется системой.
- **Оверлей** — не прозрачен для кликов обманно, наружу tapjacking чужого UI не делает (сам маленький и `FLAG_NOT_FOCUSABLE`).

## Что требует телефона (шаги для тебя)

- **F3 PoC:** включить VPN, из `adb shell` (или другого приложения) просканировать `127.0.0.1`, найти mixed-порт, `curl --socks5 127.0.0.1:<port> https://api.ipify.org` → пришли, вернулся ли IP VPN-выхода.
- **F4:** включить VPN, выключить Wi-Fi/включить LTE прямо во время трафика, параллельно смотреть на сервере свой IP — ловим окно с реальным адресом. Отдельно: дождаться авто-переключения в compat (`stop→connect`) и то же.
- **F5:** могу собрать вредоносный `.mmdb` с циклическим указателем — импортируешь через «Импортировать базу», ждём краш. Скажи — сделаю файл.
- **F8:** открой экран «Подписка», свернись в «Недавние» — видна ли там ссылка с токеном.
