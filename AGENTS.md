## 1. Что это за проект и зачем

**Fast VPN** — VPN-клиент по пользовательской подписке, с отдельным режимом для игроков
**Mobile Legends: Bang Bang** (`com.mobile.legends`) из России. Своих серверов у проекта нет:
пользователь вставляет ссылку подписки своего VPN-сервиса (тот же формат, что у Karing / Hiddify /
v2rayNG), а приложение само парсит список серверов, подбирает самый быстрый, подключается и, по
желанию, запускает игру.

Проект — это **монорепа из двух самостоятельных приложений + лендинг**:

| Директория    | Что это                                                        | Платформа        | Статус           |
|---------------|----------------------------------------------------------------|------------------|------------------|
| `mlbb-overlay/` | **Основное приложение** — Android-клиент (Kotlin + нативка)   | Android (APK)    | Активная разработка |
| `fastvpn-pc/`   | Десктоп-версия (Wails: Go + веб-UI)                          | Windows (.exe)   | Стабильна, правок мало |
| `docs/`         | Лендинг/гайд на GitHub Pages (buninsil.github.io/nextjs-chat) | статический HTML | Обновляется руками |

**Основная работа сейчас идёт в `mlbb-overlay/`** (Android). PC-версия — порт той же логики на Go,
её трогаем только если явно просят.

Три функции Android-приложения:
1. **VPN-клиент** со встроенными ядрами sing-box (libbox) и Xray.
2. **Плашка поверх игры** — показывает боевой сервер MLBB (флаг, город, пинг, IP; зелёная если РФ,
   красная если закинуло за границу).
3. **Инструменты для игры** — тест скорости, игровой Wi-Fi без энергосбережения, лог соединений в CSV.

Есть режим **«⚡ Fast VPN»** (выбирается при первом запуске) — только VPN по подписке, без всего MLBB-обвеса.

Для кого: автор (**BuninSil**) и узкий круг тестировщиков. Распространение — APK из GitHub Releases
и автообновление внутри приложения.

## 3. Как собрать и запустить с нуля

### 3.1 Android APK (основной артефакт)

Сборка идёт в CI (GitHub Actions) при каждом пуше в `mlbb-overlay/**`. Локально — так же через
Gradle wrapper. Команды (проверено, рабочие — так собирает CI):

```bash
cd mlbb-overlay

# Предусловия (один раз). В CI ставится так:
#   sdkmanager --install "ndk;26.3.11579264" "cmake;3.22.1" "platforms;android-34" "build-tools;34.0.0"
# JDK 17 + Android SDK должны быть в PATH / ANDROID_HOME.

chmod +x gradlew
./gradlew --no-daemon --stacktrace assembleDebug -PversionCode=<N>
# APK: app/build/outputs/apk/debug/app-debug.apk
```

- `-PversionCode=N` задаёт `versionCode = N` и `versionName = "1.0.N"`. В CI `N = ${{ github.run_number }}`.
  Без флага — `versionCode = 1`. Этот же `N` идёт в тег релиза `mlbb-v1.0.N`.
- Собирается **debug**-APK (подписан фиксированным `app/debug.keystore`, пароль `android` — это
  стандартный debug-ключ, не секрет; см. §9 и §10). Release-типа нет: debug-подпись нужна, чтобы
  APK из разных CI-сборок ставились поверх друг друга.
- Нативная часть (`src/main/cpp`) собирается автоматически через `externalNativeBuild { cmake }`.

Тестов как таковых в Android-модуле **нет** (юнит-тестовой папки `src/test` нет). Проверка —
`assembleDebug` компилируется без ошибок + ручная установка на устройство.

### 3.2 Windows exe

```bash
cd fastvpn-pc
go test ./...            # есть тесты (subscription_test.go)
# дальше только на Windows:
#   go install github.com/wailsapp/wails/v2/cmd/wails@v2.10.2
#   положить sing-box.exe -> bin/fastvpn-core.exe, xray.exe -> bin/fastvpn-xray.exe
#   wails build -s -clean -nsis -trimpath -webview2 embed -ldflags "-X main.appVersion=1.0.N"
# Результат: build/bin/FastVPN.exe и установщик *installer*.exe
```

`go test ./...` работает на любой ОС и быстрый — **запускай его после правок в `fastvpn-pc/`**.

### 3.3 Готовые сборки без локальной компиляции
- Последний debug-APK лежит в ветке `apk-builds` (файл `fast-vpn-debug.apk`, перезаписывается каждой сборкой).
- Последний PC-installer — в ветке `pc-builds`.
- Релизы пользователям — только из `main` (см. §10).

## 5. Архитектура Android-приложения

Пакет `dev.mlbb.overlay`, `applicationId = dev.mlbb.overlay`, видимое имя — **Fast VPN**.

### 5.1 Точки входа
- **`App.kt`** — `Application`: глобальный crash-handler (пишет версию и стек в журнал отчёта),
  инициализация.
- **`MainActivity.kt`** (1253 стр.) — главный экран: кастомные вью, глобус (`GlobeView`),
  звёздное поле (`StarField`), кнопка подключения (`ConnectRing`), запуск теста скорости.
  Прочие экраны: `ServersActivity`, `SettingsActivity`, `AppsActivity`, `AppearanceActivity`,
  `MatchesActivity`, `LogActivity`.
- **Фоновые входы:** `VpnTile` (плитка в шторке, вложена в `Widget.kt`), `Widget$Provider`
  (виджет рабочего стола), `AutoConnect$Job` / `AutoUpdate$Job` (JobService), `AutoUpdate$ReplacedReceiver`.

### 5.2 Ядро VPN и выбор сервера (главная логика)
Это то, над чем идёт основная работа. Поток: `Connector.connect()` → поднять ядро → выбрать сервер → сторож.

- **`Connector.kt`** (`object Connector`) — оркестратор подключения:
  - `connect(ctx, onReady)` → `startAndWait()` → `afterStart()`.
  - `rank(ctx, game, onWorking)` — выбор сервера. **Не-игровой режим:** быстро берёт рабочий сервер
    по опыту (`ServerTester.pickWorking` поверх `Autopilot.order`), сразу зовёт `onWorking()`
    (помечает «готово»), а полный замер скорости (`ServerTester.measure` + `pickFastest(firstWins=true)`
    + `markRanked`) гонит в фоновом потоке. **Игровой режим** — сначала полный замер, выбор по пингу.
  - `startWatchdog(ctx)` — сторож качества текущего соединения (см. ниже).
  - `onNetworkChanged(ctx, why)` — реакция на смену сети; `switchToStandby()` — быстрый переход на запасной.
  - `refine()`/`quickRefine()` — дозамер в фоне; `checkBypass()`/`bypassLabInBackground()` — подбор обхода блокировок.
- **`ServerTester.kt`** (`object ServerTester`, 829 стр.) — измерения и выбор:
  - `measure(ctx, progress)` — полный прогон пинга/скорости по всем серверам.
  - `pickFastest(ctx, ranked, candidates, firstWins, progress)` — выбор по **комбинированному скору**
    `score = speed × pingF × stab` (скорость × пинг-фактор × стабильность из Autopilot), пол 3 Мбит/с.
    `firstWins=true` — ручное подключение переключается на первом же замере; иначе — гистерезис
    (плановая проверка требует подтверждения; **не уходит с «достаточно быстрого» текущего сервера
    ≥30 Мбит/с, пока новый не быстрее в 2 раза**).
  - `pickWorking(ctx, ranked, maxTries)` — быстро находит первый живой сервер (для мгновенного «готово»).
  - `pickLowPing()` — выбор по минимальному пингу (звонки/игры).
  - `internetUp(ctx)` — проверка «есть ли вообще интернет». **Требует РЕЗОЛВА российского эталона**
    (`RU_REFS = ya.ru, vk.com, gosuslugi.ru, dzen.ru`) + TCP:443; если ни один не резолвится/не
    отвечает — это «сети нет», а не «сервер мёртв». (Фикс: раньше был fallback по голому IP и врал.)
  - `baseline3(tag)` — базовый пинг сервера (медиана свежих замеров) для сторожа.
  - `isRussian(node)` — сервер в РФ; `netKey(ctx)` — ключ текущей сети; `rankingStale()` — пора ли перемерять.
- **`Autopilot.kt`** (`object Autopilot`, 450 стр.) — память об опыте **по каждой сети** (оператор+регион):
  - Thompson sampling (`confidence` через beta-распределение), `order()` — порядок серверов по опыту,
    `leader()` — лучший кандидат, `record(ok, mbps)` / `recordPing()` — запись исхода.
  - **`quarantined(ctx, node)`** — сервер, упавший ≥2 раз за 6 ч, в карантине 90 мин (автовыбор его не берёт).
  - Данные персистятся (`save`/`load`), ключ сети — `networkKey()`/`computeKey()` (оператор + регион по гео).
- **`BoxConfig.kt`** (`object BoxConfig`) — генерит JSON-конфиг sing-box: TUN, FakeIP, селекторы
  (`proxy`/`probe`/`abroad`/`tg`/`lowping`), правила маршрутизации (`action: sniff/hijack-dns/reject/direct`,
  `ip_is_private`, порт 853 DoT→reject ВЫШЕ правила `ip_is_private`→direct, РФ-домены напрямую через `.srs`).
  `build(...)` возвращает конфиг; `Ports` — локальные порты (Clash API, mixed/socks).
- **`BoxVpnService.kt`** (`class BoxVpnService : VpnService(), PlatformInterface`) — собственно VPN-сервис:
  поднимает libbox, реализует `PlatformInterface` (openTun, findConnectionOwner, мониторинг интерфейсов),
  foreground-уведомление со скоростью/трафиком. `start()`/`stop()`/`requestRestart()`.
- **`XrayCore.kt`** — запускает процесс Xray (`libxray.so`) для серверов XHTTP/splithttp; `log.access=none`
  чтобы не засорять журнал; `tcpKeepAliveInterval=15` в sockopt (Telegram не рвётся по idle CDN).
- **`ClashApi.kt`** — HTTP-клиент к Clash API ядра: `/proxies/{tag}/delay`, select, now.

### 5.3 Нативная часть (`src/main/cpp/`)
- `tunbridge.c` + `zdtun/` (vendored, см. `zdtun/VENDORED.txt`) — мост TUN↔SOCKS5 для
  **`CaptureVpnService.kt`**: это отдельный «capture» VPN, который НЕ гоняет трафик наружу, а только
  перехватывает, чтобы показать, к какому боевому серверу подключён MLBB. Собирается через CMake.

### 5.4 MLBB-обвес (плашка и мониторинг)
- `MonitorService.kt` — показывает боевой сервер **без** VPN (через Shizuku-чтение сокетов).
- `CaptureVpnService.kt` — то же через локальный capture-VPN (без Shizuku).
- `GameServers.kt` — база/определение боевых серверов MLBB; `MatchTracker.kt` — трекинг матчей.
- `OverlayController.kt`, `GlobeView.kt`, `StarField.kt` — оверлей и графика.
- `Shizuku*`, `ProcReaderService.kt`, `UidResolver.kt`, `ConnTracker.kt`, `aidl/IProcReader.aidl` —
  чтение таблицы сокетов (кто куда подключён) правами adb-шелла.

### 5.5 Подписка, гео, обновления, прочее
- **`Subscription.kt`** (848 стр.) — парсинг подписки: vmess/vless/trojan/ss + массив Xray (`parseXrayArray`),
  запоминание User-Agent, резерв памяти под большие подписки. Модель `Subscription.Node`.
- `GeoDb.kt` + `MmdbReader.kt` + `assets/geo/` — определение страны по IP (глобус, флаги).
- `Updater.kt` / `AutoUpdate.kt` / `UpdateFlow.kt` — автообновление из GitHub Releases (`BuildConfig.UPDATE_REPO`).
- `Report.kt` + `AppLog.kt` — журнал и «Сообщить о проблеме» (файл-отчёт). `AppLog.name()` использует
  `Ui.cleanName()` — URL-декодит `+`→пробел и срезает флаг-эмодзи из имён серверов.
- `Backup.kt` — перенос настроек на новый телефон. `SpeedTest.kt`/`Pinger.kt`/`Net.kt`/`MyIp.kt` — сеть.
- `TelegramRoute.kt`/`TgProxy.kt` — маршрут Telegram; `WifiBoost.kt` — игровой Wi-Fi без энергосбережения;
  `BypassLab.kt` — перебор параметров обхода (fragment и т.п.).

### Что работает (подтверждено тестировщиками, вошло в релиз 1.0.182)
- VPN поднимается, автовыбор сервера по скорости+пингу+стабильности, маршрутизация РФ напрямую, блок рекламы.
- Ночью 7 ч без лишних переключений, DoT (порт 853) корректно отбивается.
- Темы, плитка/виджет, автоподключение по сети, выбор приложений через VPN, подписка с автообновлением,
  избранные/скрытые серверы, тест скорости, лог соединений в CSV, плашка боевого сервера MLBB, отчёт о проблеме.

### Сделано поверх 1.0.180 (блок A, вошло в боевой релиз 1.0.182)
- `internetUp` строгий: требует резолва РФ-эталона; 0 из N ответов = «сети нет», не «сервер мёртв» (фикс 1.1).
- «Готово» помечается сразу после первого рабочего сервера; полный пинг всех серверов — в фоне (фикс 1.2,
  было «готово за 36990 мс»).
- База сторожа — скользящая медиана последних ~12 удачных замеров без пола (фикс 1.3, застревала на 574 мс
  при реальных 220–260).
- Имена серверов в отчёте URL-декодятся (`Финляндия+|+Trojan` → пробелы) в `Ui.cleanName()` (фикс 1.4).
- Карантин сервера, падавшего ≥2 раз за 6 ч — автовыбор его не берёт 90 мин (`Autopilot.quarantined`, фикс 2.1).
- На плановой проверке не уходим с «достаточно быстрого» (≥30 Мбит/с) текущего сервера, если новый не
  быстрее в 2 раза (гистерезис в `pickFastest`, фикс 2.2).

### Известные баги / что сломано или не доделано
Фидбэк тестировщика на Xiaomi (2511FPC34G, HyperOS, Wi-Fi), **ещё НЕ реализовано** — это приоритет §7:
- **После сна экрана TG не грузит.** Таймеры в Doze/HyperOS тормозят; сторож просыпается поздно.
  Воспроизведение: включить VPN → погасить экран на несколько минут → разблокировать → сразу открыть
  Telegram. Нужен мгновенный пинок проверки по `ACTION_SCREEN_ON`/`ACTION_USER_PRESENT`.
- В журнале **нет** событий экран вкл/выкл и вход/выход Doze — из-за этого баг недиагностируем.

## 7. Что делать дальше (приоритет сверху вниз)

> Собирать после каждого блока (пуш в рабочую ветку запускает CI) и проверять, что APK компилируется.

1. **Сторож после сна (Tester-2 #2.3).** Добавить `BroadcastReceiver` на `ACTION_SCREEN_ON`,
   `ACTION_USER_PRESENT`, `ACTION_DEVICE_IDLE_MODE_CHANGED` и на возврат сети → немедленная проверка
   текущего сервера (пинг ≤3 с). Если не отвечает И интернет есть (`ServerTester.internetUp`) —
   переключиться на запасной СРАЗУ, не дожидаясь второго падения. Писать в журнал переходы экрана и Doze
   (сейчас их нет). Регистрация ресивера — динамически в `BoxVpnService` (эти intent'ы нельзя ловить из
   манифеста). Основную логику переключения переиспользовать из `Connector.switchToStandby`.
2. **Foreground-сервис переживает сон (Tester-2 #2.5).** Проверить, что `BoxVpnService` с
   `foregroundServiceType="specialUse"` (уже в манифесте, разрешение `FOREGROUND_SERVICE_SPECIAL_USE` есть)
   не убивается при погашенном экране на Android 14+. При необходимости — wakelock на время проверки
   (`WAKE_LOCK` уже в манифесте).
3. **Подсказки для Xiaomi/HyperOS/MIUI (Tester-2 #2.4).** На этих прошивках показать подсказку с кнопками:
   «Автозапуск», «Контроль активности → Нет ограничений», «Постоянная VPN» — intent'ы на эти экраны,
   fallback на настройки приложения. Определять вендора по `Build.MANUFACTURER`/`Build.BRAND`.
4. **Горячее переключение без рестарта ядра (архитектурное, Tester-2 #2.3 доп.).** Сейчас смена сервера
   = рестарт sing-box. Перейти на `selector`/`urltest` ядра с `interrupt_exist_connections=false`, чтобы
   переключаться без разрыва TUN. **Требует проверки на устройстве** — не ломать текущий рабочий путь.
5. Прочее отложенное (по убыванию): приоритет mux/транспорта; таймаут/параллельность/кэш DNS; пропускная
   способность XHTTP loopback-цепочки (нужен спидтест на устройстве); по-доменный fallback РФ-напрямую→прокси.

Для каждой задачи: один коммит на пункт, сообщение на русском, после блока — дать CI собрать и убедиться,
что `assembleDebug` зелёный (логи CI: прогон в Actions, грепать `e: .*\.kt` в упавшем job'е).

## 8. Принятые решения и грабли (что уже пробовали)

- **База сторожа без пола.** Пробовали фиксировать базовый пинг минимумом при выборе сервера — она
  застревала (574 мс при реальных 220). Решение: скользящая медиана последних удачных замеров, пол убран.
- **`internetUp` без fallback по голому IP.** Fallback по IP врал: при name error на `vk.ru` говорил
  «сервер мёртв», хотя это DNS/сеть легла. Теперь обязателен резолв РФ-эталона.
- **Порт 853 (DoT) reject ВЫШЕ `ip_is_private`→direct.** Иначе DoT на шлюз TUN (приватный IP 172.19.0.2)
  попадал в `direct` и Android не откатывался на обычный DNS. При локальной проверке `action: reject`
  быстро отбивает публичные IP (~12 мс), но на приватные через socks-inbound висит ~5 с — это, похоже,
  артефакт локального socks-теста, на устройстве 853 «ушёл» (подтверждено).
- **«Готово» не ждёт полный пинг.** Раньше ждали прогон всех ~71 серверов (36 с). Теперь — первый рабочий,
  полный пинг в фоне.
- **Xray `log.access=none`.** Строки `accepted tcp ... [in-nX -> nX]` раздували журнал — отключили.
- **Выбор сервера — комбинированный скор, не чистый пинг.** По одному пингу выбирался сервер 1 Мбит/с.
- **iOS-версию НЕ делаем.** Рассматривали порт на айфон — упирается в платный Apple Developer аккаунт
  ($99/год) и полный rewrite на Swift/NetworkExtension; владелец отказался. Плашка MLBB и чтение сокетов
  на iOS невозможны в принципе (ограничения Apple). Если спросят про айфон — ответ: своя подписка в
  готовом клиенте (Karing/Streisand, то же ядро sing-box). Новых заходов на iOS-порт не предлагать.
- **Приложение здесь (в CI-контейнере) не запустить.** Нет эмулятора/устройства и графики. Проверка =
  `assembleDebug` компилируется без ошибок + ручной прогон тестировщиком на реальном телефоне. Логику,
  зависящую от Doze/экрана/реальной сети, вживую не проверить — пиши аккуратно и полагайся на журнал отчёта.

### Жёсткие ограничения (НЕ нарушать)
- **Релиз в `main` / выпуск обновления пользователям — только с явного разрешения человека.** Рабочая
  ветка собирает APK для тестов, но пользователям его не отдаёт (CI публикует релиз только из `main`).
- **Не трогать** проверку подписи APK и пароли локального SOCKS-прокси.
- **Не менять** игровой режим MLBB и приоритет РФ-серверов.
- **Не ломать** уже работающие функции (см. §6).
- Сообщения коммитов — **на русском, без trailer-строк** (без `Co-Authored-By` и прочих подвалов),
  если человек не попросил иначе.

## 9. Внешние сервисы, API, ключи

Проект **не требует секретов для сборки**. Своих серверов/бэкенда нет.

- **VPN-серверы** — не наши: пользователь вводит ссылку подписки в приложении на устройстве. В репе
  никаких ключей/подписок нет и быть не должно.
- **`GITHUB_TOKEN`** — выдаётся GitHub Actions автоматически (`secrets.GITHUB_TOKEN`), используется в CI
  для публикации релизов и пуша в ветки `apk-builds`/`pc-builds`/`libbox`/`xraybin`. Руками ничего задавать не надо.
- **`debug.keystore`** (`mlbb-overlay/app/debug.keystore`) — намеренно в репе. Это **debug**-ключ со
  стандартным паролем `android` (alias `androiddebugkey`). Публичное знание, не секрет. Нужен, чтобы
  CI-сборки ставились поверх друг друга. **Release-keystore в репу не класть никогда.**
- `BuildConfig.UPDATE_REPO = "BuninSil/nextjs-chat"` — откуда приложение тянет обновления (задано в
  `build.gradle.kts`, меняется и в UI).
- **`.env` не нужен** — поэтому `.env.example` не создавался. Если появится серверная часть/ключи —
  создать `.env.example` с именами переменных (без значений) и добавить `.env` в `.gitignore`.

## 10. CI/CD (GitHub Actions)

Все workflow в `.github/workflows/`. Триггер — пуш по путям + `workflow_dispatch`.

| Workflow | Когда | Что делает | Куда кладёт |
|---|---|---|---|
| `mlbb-overlay-apk.yml` | пуш в `mlbb-overlay/**` | `assembleDebug -PversionCode=<run_number>` | артефакт `fast-vpn-debug`; APK в ветку `apk-builds`; **релиз `mlbb-v1.0.N` только из `main`** |
| `fastvpn-pc.yml` | пуш в `fastvpn-pc/**` | `go test` + `wails build -nsis` на windows | артефакт; ветка `pc-builds`; **релиз `pc-v1.0.N` только из `main` + ручной запуск** |
| `libbox.yml` | ручной / правка workflow | собирает `libbox.aar` (sing-box v1.11.4) под Android | ветка `libbox` (оттуда берётся `app/libs/libbox.aar`) |
| `xray.yml` | ручной / правка workflow | собирает `libxray.so` (Xray v26.9.30) android/arm64 | ветка `xraybin` (оттуда берётся `jniLibs/.../libxray.so`) |

- `versionCode` = номер прогона CI (`github.run_number`); он же в `versionName` и в теге релиза.
- Обновить ядро VPN = запустить `libbox.yml`/`xray.yml`, забрать артефакт из ветки, положить в `mlbb-overlay/app/...`, закоммитить.
- Как смотреть результат: GitHub Actions → прогон. При падении компиляции грепать лог job'а по `e: .*\.kt`.

## 11. Код-стайл и соглашения

- **Kotlin:** `kotlin.code.style=official`, `nonTransitiveRClass=true`. Многое — в `object`-синглтонах
  (`Connector`, `ServerTester`, `Autopilot`, `BoxConfig`). UI без Compose: вью/Canvas вручную.
  Комментарии и строки — на русском. Избегать expression-body-функций с `return` внутри (ловит
  «Returns are not allowed for functions with expression body» — уже наступали).
- **Go:** стандартный `gofmt`, пакет `main`, файлы по зонам (`subscription.go`, `tester.go`, `connector.go`…).
- **Коммиты:** на русском, одна осмысленная задача на коммит, в сообщении — что и зачем (а не как). Для
  фидбэк-задач принят формат вроде `Фидбэк-1.2/1.3: ...` или `2.4 ...`. Trailer-строк не добавлять.
- **Строки UI** — в `res/values/strings.xml`.
